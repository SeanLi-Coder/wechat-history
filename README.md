# 拾聊

macOS 微信本地压缩备份与离线聊天阅读器。只监听 `127.0.0.1`，无需注册或云服务。可以保存微信原始文件，也可以把聊天和已下载的图片、语音、视频整理成独立可读的压缩归档；读取和转换均在本机完成。

## 当前能做什么

- 自动发现常见 Mac 微信数据目录，手动或每天 / 每小时创建完整 ZIP 备份，包含目录内的数据库、图片、视频与附件。
- 自动备份默认关闭，需要在设置中主动开启。启用后每 15 分钟检查一次是否到期，微信运行时延后执行，跨午夜仍会补做最近一次到期的备份，不会补做启用计划之前的日期。电脑需要开机且用户已登录，休眠期间不会唤醒电脑。
- 保存历史版本，附带文件清单和 SHA-256 校验；检测备份期间源文件变化，失败时清理未完成归档，不报告成功。
- “打开归档”同时识别可读 ZIP 和原始 `wechat-*.zip`。含有多个微信账号时，先选择要阅读的账号；各账号分别整理和缓存，不混合消息与媒体。原始备份首次打开时使用本机已配置的对应密钥，校验并整理成独立只读阅读库，保留可用媒体和头像；不修改原 ZIP，也不合并进本机记录。再次打开复用缓存。
- 阅读页顶部“导入”支持将拾聊可读 ZIP 中的消息、头像和已保存媒体合并到本机，保留现有记录并跳过重复消息。导入后不再依赖原 ZIP。也支持 ChatLab JSON / JSONL、通用 JSON、CSV、TXT，按会话离线阅读；搜索会话名、用户名（已导入的发送者名称）和聊天关键词，点击消息结果可查看前后文。中文、英文及百分号等字符按字面匹配。
- 消息搜索可按北京时间选择开始、结束日期，也可只选日期；结束日期包含当天全部消息。全局搜索和会话内搜索均支持日期与关键词组合，结果显示完整日期时间，已有归档无需重新导入。
- 深色聊天界面采用会话列表、聊天气泡和分组时间，默认按最新到最旧排列，继续加载可查看更早的消息；搜索结果及其前后文使用同一顺序。图片、语音、视频直接在消息中查看。窄窗口可在会话列表与聊天之间切换。阅读器为只读，不提供发送消息功能。
- 联系人、群聊和消息发送者可显示本机微信缓存的头像，搜索结果与消息前后文也会显示。头像按真实账号标识关联并按内容去重，不联网下载；重新导入微信后，新建可读归档会包含头像，离线仍可显示。缺失头像使用文字占位，已有旧归档继续兼容。
- 提供本人的逐库密钥后，可校验并解密微信 4.x 数据库，将联系人、普通聊天和本机可用的媒体导入阅读器；当前不包含公众号消息。后续备份会更新阅读库，已导入的同一分库消息不会重复添加。
- 标准图片保留原文件字节；支持部分微信 DAT 图片的本地解密。语音保留原始 SILK，并生成 FLAC 供播放；视频重新封装为 MP4，不重新编码画面和声音。
- 按内容去重保存媒体，对适合压缩的内容使用无损压缩。相同媒体被多条消息引用时只存一份。
- 阅读页顶部“导出全部”可把当前本机库或已打开归档的全部会话、消息、头像和已保存的图片、语音、视频及原件保存为 `readable-*.zip`，不受关键词或日期筛选影响。可单独选择导出目录，查看完整数量、缺失媒体和完成后的 ZIP 大小，不改变定时备份设置。
- 原始可读导入文件另存 gzip 副本；完全相同的文件重复导入会跳过。不同导出文件作为独立导入保留。
- v0.8 起的应用安装包支持自动检查和下载软件更新，默认每 12 小时检查一次。精确匹配已安装版本时优先下载更小的文件增量包，否则下载完整应用；设置中可关闭自动更新，也可手动检查。

**微信 4.x 原始数据库已加密，首次阅读原始备份需要对应的数据库密钥。** 可读 ZIP 不需要密钥。已在 macOS 26.7.1、WeChat 4.1.15 验证过本地读取流程，其他版本可能需要适配。取钥与聊天导入是两个独立步骤；取钥由用户手动启动，默认不会执行，不修改原版微信或 SIP。

原始 `wechat-*.zip` 每次仍是完整备份，不做跨版本去重。每份 `readable-*.zip` 也各自包含所需数据，互不依赖；其媒体去重作用于本机媒体库和单份归档，不会让多个历史 ZIP 共用一份外部素材。加密数据库、JPEG、FLAC、MP4 等已压缩内容的额外压缩率可能较低。不会自动删除旧备份，请为保留多个版本预留空间。

## 安装与启动

直接下载 [M 系列 Mac 安装包（DMG）](https://github.com/SeanLi-Coder/wechat-history/releases/download/v0.8.1/shiliao-0.8.1-macos-arm64.dmg)。发行版仅支持 **Apple Silicon（M 系列，arm64）**，要求 **macOS 15 或更新版本**。安装包内置 Python、SQLCipher、FFmpeg / ffprobe 和所需 Python 依赖；使用者无需另装 Python 或 Homebrew。界面仍在默认浏览器中显示。

1. 在苹果菜单“关于本机”确认芯片为 Apple M 系列，下载上面的 DMG；[Releases](https://github.com/SeanLi-Coder/wechat-history/releases) 也提供包含相同应用的 `.app.zip`。`source.zip` 是供开发者使用的源码包。
2. 打开 DMG，将“拾聊.app”拖到“应用程序”；使用 `.app.zip` 时，解压后同样移到“应用程序”。请从这个固定位置打开，再设置定时备份。
3. 首次打开可能出现 macOS 安全提示。本版本使用 ad-hoc 签名，**尚未获得 Developer ID 签名和 Apple 公证**。确认文件来自项目 Release，并按随附 SHA-256 校验文件核对后，可按照 [Apple 的说明](https://support.apple.com/en-us/102445)，先尝试打开，再到“系统设置 → 隐私与安全性 → 仍要打开”。系统或单位管理策略可能不允许此操作；不能保证没有警告或在所有设备上获准运行。软件不修改 Gatekeeper、TCC 或 SIP。
4. 已有拾聊可读 ZIP 时，直接点击“导入”合并到本机，或“打开归档”只读浏览，无需微信数据库密钥。读取新电脑上的原生微信记录仍需自己的有效密钥或下文的手动初始化，安装应用不会自动完成取钥。

**v0.7.x 及更早版本需要先完整安装一次 v0.8.1。** 先等备份或整理完成，退出拾聊，再替换“应用程序”中的应用。聊天资料保存在独立的用户数据目录，不随应用包替换；仍应保留自己的备份。更换应用位置后，需在新位置重新开启并保存定时设置。macOS 可能再次要求文件或其他 App 数据访问权限。

v0.8 起，应用运行期间可在设置中检查更新，下载完成后点击“重启更新”；启用自动更新时，下次启动也可安装已准备好的版本。有备份或整理任务时，先等任务完成再安装。文件增量更新只下载应用中发生变化的文件，复用的文件仍会校验；没有精确匹配的旧应用、增量包并不更小等情况会使用完整包。这里的增量针对软件更新，聊天原始 ZIP 仍是完整备份。

自动检查和下载会访问项目的 GitHub Release 与其文件服务，仅获取版本、签名清单和安装材料，不上传聊天、媒体、密钥或账号目录。关闭自动更新后，仍可离线备份和阅读，也可按需手动检查。源码运行和仅绑定本机 Python 的开发入口请使用源码更新流程。

安装包同时提供构建清单、SHA-256 校验文件与第三方源码材料。Python 原生依赖（包括 Tcl/Tk、OpenSSL、libffi 等）的上游许可另保存在应用的 `Contents/Resources/licenses/python-build-standalone/`，并随第三方材料包提供。依赖来源、许可证及对应源码说明见 [THIRD_PARTY_NOTICES.md](THIRD_PARTY_NOTICES.md)，维护者构建方法见 [docs/RELEASING.md](docs/RELEASING.md)。

## 从源码运行

开发者也可克隆仓库或下载源码包，使用 macOS 和 Python 3.10+ 运行。以下完整聊天与媒体功能已用 Python 3.11 验证；源码包不内置运行时，需要自行安装依赖，并用同一个 Python 启动 / 构建应用：

```bash
brew install sqlcipher ffmpeg
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
```

SQLCipher 用于读取带 WAL 的加密数据库；Zstandard 用于压缩消息正文；Pillow 和 cryptography 用于图片校验与解密；pilk 用于 SILK 解码；FFmpeg / ffprobe 用于音视频转换与校验。pilk 在 Apple Silicon 上可能从源码编译，需要 Xcode Command Line Tools。依赖安装可能联网，日常读取和转换不上传聊天或媒体。仅原始 ZIP 备份和通用文字导入可以使用 Python 标准库运行。

第三方依赖保留各自许可证。例如 [pilk](https://github.com/foyoux/pilk) 使用 GPL-3.0，FFmpeg 的许可证取决于构建选项；从源码运行时，以自己安装的发行包及其许可文本为准。

激活虚拟环境后运行以下命令。`Start.command` 使用系统 PATH 中的 `python3`，需要该解释器已经装好所需依赖：

```bash
python app.py
```

为开发环境构建 / 更新本机应用入口：

```bash
python scripts/build_app.py
open dist/拾聊.app
```

`build_app.py` 保留为开发入口：它使用构建时本机的 Python 路径，与 Release 中内置运行时的安装包不同，不适合复制给其他电脑。更新代码、移动应用或更换 Python 后，请重新构建并重新启用定时设置。制作可分发安装包使用 `build_tools.py` 与 `build_portable.py`，具体见发布文档。

## 首次使用

1. 在“设置”确认微信数据目录和备份保存位置。默认选择微信 4.x 的 `xwechat_files`，保留其中所有账户与媒体文件。
2. 从微信菜单选择“退出微信”，再点“立即备份”。仅关闭微信窗口不等于退出进程。
3. 在“备份档案”查看版本，点击校验检查归档内每个文件，点击 Finder 定位 ZIP。
4. 如需定时备份，在设置中主动开启并保存。自动备份默认关闭；每天的时间按北京时间计算，通常在到期后的 15 分钟内执行。关闭浏览器不会影响已安装的定时任务；在软件设置中关闭自动备份会卸载它。
5. 点击“聊天阅读”顶部的“导入”，选择拾聊可读 ZIP，查看消息、媒体与磁盘空间预览后开始合并；也可选择 JSON / JSONL / CSV / TXT 文字记录。已有内容会保留，导入完成后切回本机资料库。需要读取本机微信时，在“管理”中完成下文的本地密钥初始化，再点击“读取 / 更新聊天”。整理媒体可能需要较长时间，界面会显示进度和未能读取的原因。
6. 点击阅读页顶部“导出全部”，确认当前资料库的消息与媒体数量，选择本次保存文件夹，再开始导出。无需退出微信，导出已整理的记录不会自动读取微信新消息。完成后可点击“在 Finder 中显示”，以后用“打开归档”选择该 `readable-*.zip`。已打开的归档也能再次完整导出；此时导出的就是当前归档，不会混入本机阅读库。打开归档不会覆盖本机阅读库，点击“返回本机”即可切回。已有阅读库时，正常备份流程也会尝试生成可读归档；若失败，会保留已完成的原始备份并提示。

7. 在左侧搜索框输入用户名、会话名或聊天关键词，结果分为用户 / 会话和具体聊天记录。选择消息可查看前后文；右侧搜索框用于筛选当前会话的消息或发送者。搜索只读取当前打开的本机库或归档，不联网。

可主动导入示例对话体验界面，示例不属于真实聊天记录。

首次读取时，macOS 可能提示“拾聊”访问其他 App 的数据，请核对应用名称后在系统提示中允许。构建的应用使用原生启动器，定时任务也通过该入口运行；命令行启动时提示名称可能是 Python 或终端。界面会显示等待授权的状态，应用不会自动更改系统权限设置。

聊天快照完成后，界面会提示可以重新打开微信；媒体仍按需从本机文件整理，期间请暂勿清理或移动微信文件。文件在读取期间发生变化时，该条媒体会保留失败状态供下次重试。定时备份与手动导入使用同一操作锁，避免同时写入；定时任务遇到正在进行的操作会延后重试。

## 导入格式

拾聊导出的 `readable-*.zip` 可完整导入本机资料库，包括消息、头像、图片、语音、视频和已保存媒体原件。选择 ZIP 后先显示数量和空间预览，再分块校验并合并；ZIP 不经过浏览器上传，不受文字文件 100 MB 的限制。导入成功后可移走原 ZIP，媒体仍可独立读取。未下载或不支持的素材保持原有状态，不会在导入时补回。 部分旧归档缺少微信媒体对应的消息版本信息，这些素材仍会保存，但不会作为已确认的消息媒体显示，预览和完成结果会提示数量。

合并使用消息来源标识和完整内容核对重复，并记录可随再次导出保留的来源映射；不会只按昵称或正文合并消息。相同归档再次导入会跳过已有消息和媒体，不覆盖已有文本或有效头像。同一微信消息的不同历史内容会保留为独立版本。校验失败会回滚本次数据修改，保留此前的本机记录。

跨 Mac 阅读建议先在已有密钥的电脑打开原始备份，再点击“导出全部”，将生成的 `readable-*.zip` 复制到另一台 Mac 打开或导入，无需复制数据库密钥。只有原始 `wechat-*.zip` 时，另一台 Mac 仍需要所选账号的对应数据库密钥。多账号选择不会绕过加密。

“导入”接收拾聊可读归档，不直接合并加密的原始 `wechat-*.zip`。原始备份请先用“打开归档”整理阅读，也可再“导出全部”保存为可读 ZIP。任意其他 ZIP 不会被当作聊天包处理。“打开归档”只读浏览，不将内容合并到本机；“导入”会占用本机数据库和媒体存储空间。两种操作均不修改微信原始目录，读取已有 ZIP 无需退出微信；与备份、导出互斥，正在执行其他操作时需等待完成。

支持 [ChatLab 标准 JSON / JSONL](https://github.com/ChatLab/ChatLab/blob/main/docs/en/standard/chatlab-format.md)，解析会话名、成员名、消息正文与时间。通过这些通用格式导入的非文本消息仅显示导出的文字 / 占位内容，不自动下载链接中的媒体，也不加载外部链接或 HTML。下文的原生媒体整理针对本机微信数据库及其素材目录。

通用 JSON 示例：

```json
{
  "title": "Example conversation",
  "messages": [
    {"sender": "Alice", "text": "Hello", "timestamp": "2026-01-01T12:00:00+08:00"},
    {"sender": "Me", "text": "Hi", "timestamp": 1767240060, "is_self": true}
  ]
}
```

也接受直接的消息数组或 `{"conversations": [...]}`。时间接受 Unix 秒 / 毫秒或 ISO 8601；没有时区的日期按 Asia/Shanghai 处理。

CSV 列：`conversation,sender,text,timestamp,is_self`，其中 `conversation`、`timestamp`、`is_self` 可省略。

TXT 格式：

```text
[2026-01-01 12:00:00] Alice: Hello
This is a continuation of the previous message.
[2026-01-01 12:01:00] Me: Hi
```

不符合上述 TXT 格式的文本按原文导入，不推断发送人。单文件最多 100 MB、500,000 条消息。

## 读取原始微信数据库

“聊天阅读”支持导入已知有效的本机密钥文件：

```json
{"keys":{"message/message_0.db":{"enc_key":"YOUR_64_HEX_CHARACTER_RAW_KEY"}}}
```

实际文件需要覆盖消息分库、联系人库，以及存在的 `message_resource.db` 和 `media_数字.db` 媒体辅助库。每把密钥先用对应数据库第一页的 HMAC 验证，全部通过后才以 0600 权限保存在应用数据目录。请先从菜单正常退出微信，再进行读取；只关闭窗口不等于退出。

头像另外使用可选的 `head_image/head_image.db` 及其对应密钥。缺少头像库、密钥或有效本地图片时继续显示文字占位，不影响聊天读取，也不下载联系人资料中的远程头像链接。升级后重新读取微信并新建可读归档，可让新归档独立包含头像；已有 ZIP 保持原样。

无非空 WAL 时，使用逐页 HMAC 校验的本地解密流程；发现损坏即停止。微信正常退出后仍可能留下包含已提交事务的 WAL。对此会把主数据库及 WAL 复制到当前用户专用的临时目录，再由 SQLCipher 4.x 读取副本并导出明文库，避免只读取主库而遗漏 WAL 中的消息。安装包使用内置 SQLCipher，源码模式查找另行安装的工具；不会用 SQLCipher 对原始微信目录执行 checkpoint 或写入。非空 rollback journal 仍会拒绝处理，需要先让微信正常恢复并退出。临时明文数据库在导入结束后清理。

没有密钥时，可在 M 系列 Mac 上手动使用本项目源码中的初始化辅助程序。该流程另外依赖系统 LLDB 和匹配的 Apple Python，不承诺适用于所有微信版本。安装包内置的运行时不替代这套调试工具，也不会自动启动初始化。已有可读归档不需要此步骤。工作方式参考 [同版本的本地取钥实现](https://gist.github.com/acmerfight/0a01249ef72970d07a2603dbb629e80f)。首次操作需要退出当前微信，并可能完成手机登录确认。

```bash
# Prepare only; does not launch or stop WeChat.
python3 scripts/wechat_initialize.py prepare

# After saving drafts and quitting the official WeChat application:
python3 scripts/wechat_initialize.py capture --acknowledge-debug-copy
```

捕获阶段会用 LLDB 启动已重签的临时副本，仅观察与所选数据库 salt 匹配的密钥派生调用。副本仍使用你的原账号数据，可能要求手机确认；这时不要在副本中发送消息或编辑草稿。完成后只清理自己启动的调试进程，并请求重新启动原版。原版重新打开后，如需立即导入阅读库，请再次正常退出微信，再点击“读取微信聊天”。密钥不显示到终端或聊天中。

本版本原生读取支持普通聊天文本、联系人名、群消息发送者和跨分库合并，暂不包含公众号消息。搜索索引不作为聊天记录导入；资源辅助库用于匹配媒体。当前账号本人标识尚未自动推断，不能根据左右气泡判断是否本人发送。

## 媒体与原画质

软件优先保留本机已有素材的质量，不为了缩小体积重新压缩画面。内容相同的媒体共享一份存储对象；适合进一步压缩的对象使用 gzip，不适合的保持原字节。

- **图片：** JPEG、PNG、GIF、WebP 等受支持的标准图片不重新编码。旧 XOR、V1 和可验证密钥的 V2 DAT 会解密后保存；macOS V2 图片密钥候选来自本地账号与缓存文件名，并通过实际图片解码验证，不需要再次调试微信进程。找不到完整原图时可以保留缩略图，但会明确标注。
- **语音：** 成功整理的原始 SILK 文件一并存入媒体库和可读归档；播放副本为 FLAC，对 SILK 解码得到的 PCM 无损压缩。FLAC 不会恢复 SILK 编码之前已经丢失的音频信息，不生成机器转写。
- **视频：** 已完整下载的 MP4 / MOV 重新封装为可播放 MP4，视频和音频流直接复制，不进行有损转码。实际播放仍取决于浏览器对原视频编码的支持。本机只有封面或缩略图时，无法由它恢复完整视频。
- **WXGF：** 当前只生成并显示首帧 PNG 预览，界面会标注“首帧预览”；同时在可读归档中保存解密后的完整原始 WXGF。保存了原件不表示阅读器已经支持播放完整 WXGF 动画或 Live Photo。
- **MPO：** 保留包含所有画面的原始文件字节，阅读器显示首张画面，并明确标注多画面照片；当前不提供其他画面的切换。

媒体按会话、消息和资源记录匹配；缺失、候选不唯一、格式不支持或解密失败的条目会说明原因，不用其他文件代替。微信从未下载到本机、已经清理掉的原图或完整视频，不能仅凭消息记录恢复。对于尚未成功整理的媒体，可以先在微信中下载原素材，正常退出后重新更新阅读库。已保存的完整媒体在消息内容未变时跳过重复处理；缩略图会尝试升级为后来下载的原图，升级失败时仍保留原有可用预览。已保存的视频不会自动替换为后来出现的更高质量版本。消息身份或内容变化后，会重新核对媒体关联。已保存的媒体即使原微信目录随后移走，仍可从本机媒体库或可读归档读取。

## 打开压缩归档

阅读页的“打开归档”会识别拾聊的两种 ZIP：

- `readable-*.zip`：直接打开聊天和已保存媒体，不需要微信密钥，适合在另一台 Mac 阅读。
- `wechat-*.zip`：保留微信原始文件。首次阅读需要在管理区完成本地读取初始化或导入这个备份对应账号的密钥；程序会校验全部文件，在私密临时目录中解包、解密并整理媒体，再保存独立的只读阅读缓存。这个步骤可能较久，并需要额外磁盘空间，开始前会检查空间。失败会清理本次未完成数据，原 ZIP 保持不变。

再次打开同一份原始备份会使用已完成的缓存，不必重复全量解包，也无需再次提供密钥；缓存对应 ZIP 的文件签名和清单摘要，备份改变后会重新核对。缓存不会混入“本机记录”。只有备份中存在且能够解码的媒体才能显示，未下载、缺少图片密钥或格式不支持会保留明确状态。包含多个微信账号的原始备份目前需改选单个账号备份。整理完成后，可通过“导出全部”生成无需密钥的可读 ZIP。

备份结果中的“打开本次可读库”另行打开当次生成的完整本机阅读库，其中可能包含其他已导入记录。“打开归档”选择原始 ZIP 时始终阅读该备份的隔离副本，不会自动替换成这份完整可读库。

以下说明针对可读 ZIP：

`readable-*.zip` 包含 `library.sqlite3`、`media/objects/` 和带 SHA-256 的 `manifest.json`。它包括已保存的原始 SILK / WXGF，不包含数据库密钥。聊天、图片、音频、视频的索引和内容都保存在归档内。

“导出全部”保存当前资料库中全部已导入的消息及已保存媒体，包含未显示在当前页或搜索结果中的记录。导出时生成一致的聊天库快照，按内容去重并保留已有媒体质量；媒体已经压缩时不会为了减小体积进行有损转码。再次导出归档时直接逐项读取原 ZIP，校验内容后写入新的独立 ZIP，不需要把全部媒体预先解压到磁盘，也不会覆盖旧归档。

导出摘要分别统计全部消息、有效媒体关联、去重后的文件、头像和不可用媒体；缺失、格式不支持、未完成整理的状态会保留，不能凭记录恢复本机没有的素材。“全部”指当前已整理资料库的范围，普通文件附件及其他尚未支持的消息类型不会在此步骤自动解析；需要保留所选微信目录内所有原始文件时可使用原始 ZIP 备份。

在拾聊中打开时，先校验并载入聊天库，再按需解压请求的媒体，无需预先解压整个 ZIP。请在阅读期间保持 ZIP 文件可访问，尚未读取的媒体仍需要从它提取。读取过的内容会缓存在应用数据目录；缓存和归档都需要磁盘空间。单份归档可以独立复制到另一台已安装拾聊的 M 系列 Mac 打开，不需要保留更早的版本或重新取得微信密钥。

归档阅读库以只读方式打开，媒体会校验完整性。ZIP 没有额外密码加密，拿到文件的人可以读取其中的聊天和媒体，请按私人文件保存。

## 文件保存在哪里

- 默认备份：`~/Documents/拾聊备份/`，可在设置里更改。
- 设置与可读库：`~/Library/Application Support/Shiliao/`。
- 可读导入原文：上述目录的 `imports/*.gz`。
- 本机独立媒体：上述目录的 `media/objects/`；按需解压的媒体缓存位于 `media/cache/`。
- 可读归档：所选备份目录中的 `readable-*.zip`；打开后的临时阅读库和缓存位于应用数据目录的 `opened-archives/`。
- 原始备份阅读缓存：应用数据目录的 `opened-raw-archives/`，包含独立聊天库和整理后的媒体，不保存临时密钥副本。
- 软件更新缓存与状态：应用数据目录的 `updates/`，与聊天、媒体和备份文件分开保存。
- 定时任务：`~/Library/LaunchAgents/com.shiliao.backup.plist`，只有开启后才创建。
- 已验证的数据库密钥：应用数据目录的 `wechat-keys.json`，绝不要分享或提交到 Git。
- 初始化临时副本与私密捕获文件：应用数据目录的 `wechat-access/`。
- 日志：上述应用数据目录的 `logs/`，不记录消息正文或访问令牌。

原始 `wechat-*.zip` 内的 `manifest.json` 保存文件路径、大小、SHA-256，`data/` 是原始备份内容。可使用标准 ZIP 工具解压到一个新的空目录检查文件。不要直接覆盖正在使用的微信目录；本版本没有自动还原按钮。阅读优先选择已经整理好的 `readable-*.zip`；只有原始备份时，按上述密钥与空间要求通过“打开归档”处理。

数据目录和新归档限制为当前用户可读写；可读导入库没有额外密码加密。保存磁盘本身是否加密取决于你的 macOS / FileVault 设置。
